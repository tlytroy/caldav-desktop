## 数据来源（重要）

工作台**不做任何数据聚合接口调用**，只有一次请求：

```ts
const r = await fetchItems();          // GET /api/workspace/items（无过滤）
const calEvents = items.filter(i => !!i.start);      // → 今日事件
const todos     = items.filter(i => i.kind === "task"); // → 待办
```

历史 bug（已修）：这里原先读 `syncStore.cachedEvents`，而数据流重构后
该缓存**无人写入**，于是「今日事件」「N 个事件」恒为 0 —— 页面看着正常，全是空的。
**教训：工作台只读 workspace，不要读任何 store 里的副本。**

## 概述（原始设计稿，下方为 2026-08 版本）


工作台是用户登录后的首页，旨在提供一个统一的入口，整合各模块的概览信息，让用户能够快速了解当前状态并执行常用操作。

## 状态管理

### Store 数据依赖

| 数据         | 来源 Store             | 用途         |
| ------------ | ---------------------- | ------------ |
| 今日事件列表 | `calendarStore.events` | 今日日程展示 |
| 同步状态     | `syncStore.status`     | 同步状态指示 |
| 上次同步时间 | `syncStore.lastSync`   | 时间显示     |
| 主题偏好     | `themeStore.theme`     | 主题适配     |

### 本地 UI 状态

| 状态           | 类型      | 默认值  | 说明         |
| -------------- | --------- | ------- | ------------ |
| `searchQuery`  | `string`  | `''`    | 全局搜索输入 |
| `isRefreshing` | `boolean` | `false` | 手动刷新中   |

## 响应式布局

| 断点       | 布局       | 说明                               |
| ---------- | ---------- | ---------------------------------- |
| < 640px    | 单列堆叠   | 移动端：今日日程和快速操作上下排列 |
| 640-1024px | 双列自适应 | 平板：保持双列但卡片紧凑           |
| > 1024px   | 双列固定   | 桌面：展示完整信息                 |
