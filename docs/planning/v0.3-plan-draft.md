## 0. 一句话

把现在「能用的本地优先工作台」升级为**敢放到 NAS 上长期跑、数据不怕丢、多端可同步**的版本；

## 2. 目标 / 非目标

### v0.3 目标

1. **可安全自托管**：未授权访问被拒绝；敏感接口有基本防护；配置不泄露。
2. **数据不丢**：写入原子化、并发不互相覆盖、备份可恢复。
3. **同步可观测**：一个「同步中心」看两条通道的状态 / 冲突 / 历史；WebDAV 支持周期自动同步。
4. **本地优先不变**：任何新能力在「服务器全挂」时不影响日历 / 任务 / 提醒（应用内）使用。

### 非目标（本阶段明确不做）

- 多用户 / 账号体系 / 共享日历（只做单用户 token）
- 端到端加密
- 重复事件「只改这一次」（需要例外实例模型，排 v0.4）
- 移动端原生重写（PWA / Capacitor 现状延续）
- AI Agent、插件市场、Git 同步模块
- WebDAV 的删除传播（先做 CalDAV 墓碑，或都不做，见待决策）

## 3. 约束与原则

1. **一个数据文件**：不得引入第二个业务数据文件；状态文件（同步 etag、提醒 sent）只能是可重建的缓存。
2. **本地优先**：所有功能在无网络 / 无服务器时可用；同步与推送是可选的「外挂」。
3. **向后兼容**：已有 `workspace.md` 不改坏；新增字段必须可缺省。
4. **不引重型依赖**：认证、限流、文件锁尽量用 Node 内置实现，避免供应链风险。
5. **可测试**：每个 Epic 必须有本地可复现的测试（mock 服务端），不依赖真实 NAS。
6. **文档同步**：改行为必须改对应 `REF/` 或 `docs/`。

## 4. 候选 Epic

### E1 安全接入（AuthN / AuthZ / 暴露面）

**问题**：P1。

**范围（做）**
- 单用户 **Bearer Token**：
  - 服务端：`API_TOKEN`（env）或 `config.json` 的 `auth.token`；配置了才启用。
  - 所有 `/api/*`（除 `/health`、静态资源、`/api/auth/*`）校验 `Authorization: Bearer <token>`。
  - 未配置 token 时：仅允许本机访问（校验 `req.ip` 属于 loopback）；非本机请求返回 401 并提示配置。
  - 失败响应统一 `401 { error: "未授权" }`，不泄露「token 是否存在」。
- 前端：
  - 401 时弹出「访问令牌」输入；存 `localStorage`（或 Electron 注入）；axios 拦截器统一附带。
  - 设置页有「连接令牌」输入 + 清除；显示「已连接 / 未授权」。
- CORS：
  - 默认同源（不开启 `*`）；`CORS_ORIGINS` 可配白名单。
- 限流：
  - 登录失败 / 全部 API 的简单内存令牌桶（按 IP）；阈值可配，默认宽松（如 300 req/min）。
- 文档：
  - Docker compose 增加 `API_TOKEN` 示例；说明反代 TLS 建议。

**不做**：账号密码、注册、找回、多用户、OAuth。

**验收**
- 未带 token 访问 `/api/workspace/items` → 401；带正确 token → 200。
- 未配置 token 且从非 loopback 访问 → 401 且提示如何配置。
- 前端在 401 时能输入 token 并恢复；刷新后仍保留。
- CORS 白名单生效（不在名单的 Origin 无 `Access-Control-Allow-Origin`）。
- 限流触发时返回 429 且有 `Retry-After`。

**风险**：token 存 localStorage 有 XSS 风险（当前无用户输入 HTML 渲染；仍接受）；反代下 `req.ip` 需要 `trust proxy`，需文档说明。

**规模**：M（2–3 人日）

### E2 数据可靠性（原子写 / 并发 / 备份恢复 / 迁移）

**问题**：P2、P3，以及 schema 演进无迁移框架。

**范围（做）**
- **原子写**：写 `*.tmp` → `fsync` → `rename`；失败时保留原文件。
- **进程内互斥**：所有读-改-写 API 串行化（Promise 队列）；写入前重新读最新文件，避免请求间丢更新。
- **不变量校验**（写入前）：
  - id 唯一；`parent` 必须存在且不成环；`end > start`；`remind/start/due` 格式。
  - 现有 `validateItem` 扩展为「条目 + 图」校验。
- **备份可恢复**：
  - `GET /api/workspace/backups` 列表（时间、大小、条目数）。
  - `POST /api/workspace/backups/restore`（先备份当前 → 覆盖 → 返回 diff 摘要）。
  - 设置页 / 数据页提供入口；保留份数可配（默认 10）。
- **迁移框架**：
  - frontmatter `schema: workbench/v2`（若需要）+ `migrations/` 顺序执行；失败回滚（备份）。
  - 本阶段若字段无变化，只建立框架 + 测试，不强制升级文件。
- **损坏恢复**：全部条目 invalid 时，界面提示「从最近备份恢复」。

**不做**：多进程文件锁（Docker 与桌面同时写同一文件不支持，文档明确）、数据库化。

**验收**
- 并发 50 个创建请求 → 文件里 50 条，无丢失。
- 模拟写入中断（临时文件存在）→ 原文件仍可解析。
- 备份列表 / 恢复可用，恢复前自动备份。
- 迁移失败会回滚，不产生半迁移文件。

**风险**：Windows 上 rename 覆盖语义差异需测试；`fsync` 在部分文件系统慢（可配置）。

**规模**：M（2–3 人日）

### E3 同步中心（WebDAV 自动 + 统一状态 + 冲突历史）

**问题**：P4、P5；P6 视决策。

**范围（做）**
- 统一状态 API：`GET /api/sync/overview` 聚合 CalDAV + WebDAV：
  - 是否配置、上次成功/失败时间、错误摘要、待推送数、冲突数。
- 同步中心模块（`modules/sync`，active）：
  - 两条通道卡片、测试连接、立即同步、自动同步开关 / 间隔。
  - 冲突列表 + 三选一操作（复用现有 force / merge / pull）。
  - 最近 50 条同步历史（成功/失败/冲突），存 `.sync-history.json`（可重建）。
- WebDAV 自动同步：`webdav.autoSyncMinutes`，复用 CalDAV 的定时器模式；写操作后可选 debounce（默认关）。
- 错误可读化：401/403/404/412/5xx 统一映射中文提示。
- （可选，取决于决策）CalDAV 删除传播：
  - 本地删除记录 tombstone（uid + 时间）；push 时 DELETE 远端对象；成功后清 tombstone。
  - 远端删除是否删本地：默认不删，需显式开启 `propagateRemoteDeletes`。

**不做**：双向实时（WebSocket）、多后端冲突合并、离线队列。

**验收**
- 同步中心显示两通道真实状态；无配置时显示「未配置」而非报错。
- WebDAV 自动同步按间隔执行，可在界面改（无需重启）。
- 冲突解决后状态与历史正确落盘。
- 删除传播（若做）只删对应 uid，不误删同系列其他对象。

**风险**：多后端同时调度；tombstone 误删；WebDAV 自动同步与本地编辑竞态。

**规模**：M–L（3–5 人日，含墓碑）

## 5. 推荐 v0.3.0 切片

**E1 + E2 + E3（不含删除传播，除非决策要求）**。

理由：

1. 这三项决定「能不能放心把数据和日程放到 NAS 上」——是当前产品从玩具到日用的门槛。
2. 它们互相关联：认证保护写入面、原子写保护数据、同步中心让多端行为可解释。
3. E4/E5 是体验增强，不阻塞自托管；E5 的重复例外模型成本高，应先单独设计。
4. E6 可以顺手做（CI 修复 + typecheck 脚本），但不应占主工期。

**v0.3.0 完成定义（DoD）**

- 未授权无法读写 API（除公开端点）。
- 并发写不丢数据；写入可恢复；备份可恢复。
- 同步中心可用，WebDAV 可自动同步，冲突历史可查。
- 本地优先回归：服务器全关时日历 / 任务 / 应用内提醒仍可用（已有测试 + 手工验收）。
- 全部测试通过；`docker build` 通过；文档更新。
- 新增/修改的接口、字段、配置都有测试与文档。

## 8. 风险登记

| 风险 | 概率 | 影响 | 缓解 |
| ---- | ---- | ---- | ---- |
| token 方案被后续多用户需求推翻 | 中 | 中 | 设计成可扩展中间件；接口层不绑定单用户 |

| CI 修复引入新依赖 | 低 | 低 | 只用现有工具 |

## 附录 B：术语

- **本地优先**：无服务器也能完整使用；服务器只做可选同步 / 推送。
- **唯一事实源**：`workspace.md`；其它状态文件必须可重建。
- **墓碑（tombstone）**：记录「已删除的远端对象 uid」，用于把删除传播到 CalDAV。
- **SDS**：Software Design Specification，落到接口、数据结构、状态机、错误处理与测试的设计文档。
