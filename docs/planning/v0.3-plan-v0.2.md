## 0. 摘要

v0.3.0 不追新功能，只做三件让产品「敢长期用」的事：

1. **可信的工程基线**（M1）：修 CI，让每次改动的测试/类型/构建可信。
2. **数据不丢**（M2/M4）：原子写、统一写锁、并发/崩溃可测、备份可预览可恢复。
3. **安全接入**（M3）：fail-closed token、反代安全、Electron 无感注入、Docker 必填 token。
4. **同步可观测**（M5，可选 M6）：只读同步中心，聚合两条通道状态与历史；WebDAV 自动同步默认关。

明确不做：墓碑删除传播、迁移框架、重复事件单次编辑、多用户、AI/插件扩展。

## 3. 目标与非目标

### 目标

1. **安全**：未授权无法读写 API；token 生命周期明确；反代不被 XFF 绕过；Electron 无感。
2. **可靠**：写入原子化；所有写路径串行化；崩溃/并发可验证；备份可预览、可恢复。
3. **可观测**：一个页面看清 CalDAV/WebDAV 状态、待推送、冲突与最近历史。
4. **本地优先不变**：本地模式下，服务器全关时日历/任务/应用内提醒完整可用。

### 非目标（v0.3.0）

- 多用户、账号密码、OAuth、共享日历
- CalDAV 删除传播（墓碑）、VTODO
- 重复事件单次编辑 / EXDATE 例外模型
- 数据迁移框架 / schema v2
- 原生移动端（Capacitor）、AI Agent、插件市场、Git 同步
- 端到端加密、审计合规

## 5. 里程碑

### M1 · 工程基线（CI，0.5–1 人日）

**目标**：让测试/类型/构建在 CI 可信，保护后续所有改动。

范围：

- `.github/workflows/test.yml`：
  - Node 22；固定 pnpm（`packageManager` + `pnpm/action-setup` 或 corepack）；
  - `pnpm install --frozen-lockfile`；
  - server：`pnpm build`（`tsconfig.build.json`，排除测试）+ `pnpm test`；
  - renderer：新增 `typecheck` 脚本（`tsc --noEmit`）+ `pnpm test` + `pnpm build`；
  - 移除当前会 404 的 `pnpm typecheck` 调用；desktop 构建改为可选 job。
- 根 `package.json` 增加 `packageManager: pnpm@11.8.0`。
- 不引入 lint 框架（现有无 lint 配置）。

验收：

- push / PR 上 CI 全绿；
- 本地 `pnpm -C apps/server build && pnpm -C apps/renderer build` 通过；
- CI 日志中 `install` 使用 frozen lockfile。

风险：Node 22 与 Electron 28 的兼容；desktop job 可先不跑。

### M2 · 数据核心（E2-core，4–5 人日）

**目标**：单进程内不丢更新、崩溃不截断文件、未知内容不丢。

范围：

1. **原子写**
   - 同目录 `workspace.md.tmp.<pid>` → `fsync` → `rename`；
   - POSIX 下 fsync 目录（best-effort）；
   - Windows rename EPERM/EBUSY 重试 3 次（50ms/100ms/200ms），仍失败**报错不降级**；
   - 启动与每次写入前清理 >1h 的陈旧 tmp。
2. **统一写锁**
   - 新增 `withWorkspaceLock(fn)`（Promise 队列，进程内）；
   - 覆盖：workspace CRUD、ICS 导入、恢复、CalDAV pull 写入、WebDAV pull/merge 写入；
   - **网络 IO 在锁外**：先取远端/解析，再进入临界区「重读 → 合并 → 写」；
   - 锁超时（如 10s）返回 503 并记录；禁止嵌套调用（重入直接抛错）。
3. **不变量校验**
   - id 唯一、parent 存在、无自环/环、`end > start`、`remind` 格式；
   - 写入前校验，失败拒绝并说明条目。
4. **Round-trip 保留**
   - 解析时保留未知 `- key: value` 字段与未知块；
   - 序列化写回；条目顺序仍按现有排序规则（有意规范化，不承诺字节级保序）；
   - 测试：读入含未知字段/未知块的文件 → 写出 → 再读，未知内容仍在。
5. **并发/崩溃测试**
   - 并发 50 个 POST + 同时一次 CalDAV pull；
   - 子进程写 tmp 后 `kill -9`，验证旧文件可解析、tmp 被清理。

验收（详见第 8 节）：并发不丢更新；崩溃后可恢复；未知字段保留。

不做：跨进程文件锁、数据库化、迁移框架。

### M3 · 安全接入（E1-min，2–3 人日）

**目标**：默认安全；未授权无法访问；反代/Docker/Electron 行为一致。

范围：

1. **服务端**
   - `API_TOKEN` 环境变量**必填**：缺失时启动失败（exit 1），日志只说明如何配置，不打印 token。
   - 中间件（`createApp()` 工厂内）：
     - 公开：`GET /health`、静态资源、`OPTIONS *`；
     - 其余 `/api/*`：校验 `Authorization: Bearer <token>`；
     - 使用 SHA-256 + `timingSafeEqual` 比较；401 返回统一 `{ error: "未授权" }`。
   - 无 `/api/auth/*`。
   - CORS：
     - 默认同源（不返回 `Access-Control-Allow-Origin: *`）；
     - `CORS_ORIGINS` 逗号分隔白名单；
     - dev 默认允许 `http://localhost:5173`；
     - `Vary: Origin`；
     - Electron 若仍用 `file://`（Origin `null`），仅在「token 必经」前提下允许 `null`，并在 SDS 决定是否改用本地 HTTP 托管。
   - 反向代理：`TRUST_PROXY_HOPS`（默认 0）→ `app.set("trust proxy", n)`；文档给 Nginx/Caddy/Tailscale 示例。
   - 限流：内存固定窗口，按 IP 600 req/min；401 响应额外计数（20/min）→ 429 + `Retry-After`。
2. **前端**
   - API 客户端统一附带 token：优先 `window.__API_TOKEN__`（preload 注入），否则 localStorage；
   - 401 全局拦截 → 显示「访问令牌」输入页；输入后重试；提供清除入口；
   - 所有 API 客户端（workspace / caldav / webdav / notifications / config / nlp / plugins）统一走同一个 axios 实例或拦截器。
3. **Electron**
   - 主进程启动时生成随机 token（32 bytes hex），传给 forked server 的 env；
   - 通过 preload 注入渲染进程（contextBridge），不写入 localStorage；
   - 优先让 Electron 加载本地 HTTP 服务（同源），避免 `file://` + CORS；若保持 `file://`，按 SDS 处理 `null` origin。
4. **Docker**
   - `docker-compose.yml` 使用 `API_TOKEN: ${API_TOKEN:?请在 .env 设置 API_TOKEN}`；
   - `.env.example` 增加 `API_TOKEN=`；
   - 文档：token 轮换 = 改 env 重启；浏览器重新输入。
5. **测试**
   - 401 / 200 / OPTIONS / 代理伪造 / 限流；
   - Electron 手工验收清单（无 token 显示输入页；注入后可读写）。

不做：多用户、账号密码、session、OAuth、审计日志。

### M4 · 备份恢复（E2-ui，2–3 人日）

**目标**：备份可见、可预览、可恢复，恢复后状态一致。

范围：

- API：
  - `GET /api/workspace/backups`：文件名、时间、大小、条目数；
  - `POST /api/workspace/backups/preview`：`{ file }` → 覆盖前 diff（新增/删除/修改条数 + 前 N 条标题）；
  - `POST /api/workspace/backups/restore`：`{ file, confirm: true }`；
- 恢复流程（必须按顺序）：
  1. 暂停所有调度器（CalDAV 自动同步、WebDAV 自动同步、提醒推送）；
  2. 获取写锁；
  3. 再次预览/校验目标备份；
  4. 备份当前文件；
  5. 原子写入备份内容；
  6. 重置 CalDAV/WebDAV etag 状态、清空提醒 `sent`（或按 id 保留，SDS 定）；
  7. 释放锁、恢复调度器；
  8. 返回 diff 报告。
- UI：设置 →「数据文件」页展示备份列表、预览、二次确认恢复；导出备份文件。
- 测试：恢复后首次同步不产生全量冲突；旧提醒不重发；恢复期间同步不写入。

风险：恢复是破坏性操作；必须二次确认 + 备份当前 + 可回滚。

---

### M5 · 只读同步中心（E3a，2 人日）

**目标**：一页看清两条同步通道，不新增调度器。

范围：

- `GET /api/sync/overview`：
  - CalDAV / WebDAV 各自：configured、enabled、lastSuccessAt、lastError、pending、conflicts、autoSyncMinutes；
  - 只读现有状态文件/内存状态，不发网络请求。
- `GET /api/sync/history`：最近 20 条（`{ ts, channel, direction, pushed, pulled, merged, conflicts, errors }`），
  存 `.sync-history.json`，可清空，非事实源。
- 模块 `modules/sync`（active）：
  - 两条通道卡片；测试连接、立即同步（复用现有 API）、冲突入口；
  - 历史列表；未配置时显示「未配置」，连接失败显示错误摘要，不 500；
  - 导航项「同步中心」。
- 日历页工具栏保留快捷按钮，但状态统一由同步中心展示。

不做：新调度器、实时推送、删除传播。

## 6. 横切约束

### 6.1 状态文件分类

| 文件 | 性质 | 可否重建 | 恢复备份时 |
| ---- | ---- | -------- | ---------- |
| `.workspace-backups/` | 恢复材料 | 否（历史快照） | 不覆盖 |
| `.caldav-sync-state.json` | 缓存（etag/字段快照） | 是 | **重置** |
| `.webdav-state.json` | 缓存（etag） | 是 | **重置** |
| `.reminder-state.json` | 缓存（已推送） | 是 | **清空或按 id 保留**（SDS 定） |
| `.sync-history.json` | 日志 | 可清空 | 保留（可选） |
| `workspace.md` | 唯一事实源 | 否 | 恢复目标 |

### 6.2 错误与响应

- 401：`{ error: "未授权" }`（不区分「未配置/错误」）；
- 409：冲突/前置条件；
- 412：ETag 不匹配（同步层已有）；
- 429：`Retry-After`；
- 503：锁超时/维护中；
- 所有错误响应不得包含 token、文件绝对路径（日志可）。

### 6.3 依赖与兼容

- 运行时零新增依赖；
- Node ≥20（CI 用 22）；Express 4；
- 旧 `workspace.md` 可直接读；未知字段不丢；
- 旧 API 路径保持不变；新增仅 `/api/sync/*`、`/api/workspace/backups/*`。

### 6.4 测试数据

- 认证测试使用固定 `API_TOKEN=test-token`；
- 同步/并发测试使用临时目录；
- Docker 冒烟使用临时 volume。

## 8. 验收（可执行）

1. **认证**
   - `curl -i http://127.0.0.1:3001/api/workspace/items` → 401；
   - `curl -i -H "Authorization: Bearer $TOKEN" ...` → 200；
   - `curl -i http://127.0.0.1:3001/health` → 200。
2. **OPTIONS**：带 `Authorization` 的预检 → 204，含正确 ACAO，不因无 token 被拒。
3. **代理**：`TRUST_PROXY_HOPS=1` + `X-Forwarded-For: 127.0.0.1` 无 token → 401。
4. **Electron**：无 token 首次打开 → 令牌页/自动注入；注入后读写正常；刷新不丢。
5. **并发创建**：50 个 POST → 全部落盘，无重复 id。
6. **并发更新**：同一 item 的 `title` 与 `due` 两请求 → 两字段都保留。
7. **并发同步**：50 请求 + CalDAV pull → 条目数正确、无解析错误。
8. **崩溃**：写 tmp 后 kill -9 → 重启文件可解析，tmp 清理。
9. **恢复**：恢复 3 天前备份 → 覆盖前 diff；恢复后首次同步不全量冲突；旧提醒不重发。
10. **同步中心**：未配置 / 连接失败 / 有冲突三种状态正确显示，不 500。
11. **自动同步**：1 分钟间隔 + 连点手动同步 → 只一轮请求；412 转人工。
12. **round-trip**：未知字段/块读入后写出仍在。
13. **Docker**：`docker build` + 容器冒烟；`data/workspace.md` 可读写。
14. **本地模式断网**：停掉 CalDAV/WebDAV/推送后，日历/任务/应用内提醒可用。

## 11. 开放技术问题（留给 SDS）

1. Electron 采用「本地 HTTP 同源」还是「file:// + null origin」？token 用 preload 的哪种形态？
2. 未配置 `API_TOKEN` 时启动失败，开发模式是否有例外？（建议无例外，dev 写死 env）
