## 2. 数据层设计（M2）

### 2.1 读取语义

```ts
export class WorkspaceReadError extends Error {
  readonly code = "WORKSPACE_READ_FAILED";
  constructor(public filePath: string, public cause?: unknown) { ... }
}

export interface WorkspaceFile {
  items: ParsedItem[];
  notes: string;
  /** 原始 frontmatter 文本（含 --- 行）；v0.3 不改写，保留 schema/列表/注释 */
  frontmatterRaw?: string;
  unknownBlocks?: string[];
  filePath: string;
  /** 原始文件文本；merge 的 baseline 与 unknown 保留依赖它 */
  raw: string;
}

export function readWorkspace(filePath?: string): WorkspaceFile;
```

规则：

1. **只用 `readFileSync` 的错误码判 ENOENT**，不得先用 `existsSync`：
   `try { text = readFileSync(...) } catch (e) { if (e.code === "ENOENT") return empty; throw new WorkspaceReadError(...) }`。
   EACCES/EISDIR/EIO 一律 throw，避免「读空 → 写空」清空事实源。
2. `ENOENT` → `{items:[], notes:"", frontmatterRaw: defaultFrontmatter(), unknownBlocks:[], raw:""}`。
3. 内容非空、含 `## ` 块，但**没有一条可解析条目**（既无 `id`，也无任何已知字段）→
   throw `WorkspaceReadError("全部条目无法解析")`。错误响应只给相对文件名/提示，**不给绝对路径**。
4. 部分条目坏 → 保留 `ParsedItem.errors` + `rawBlock`，其余可用；写回时坏块原样保留（2.5）。
5. 定义：
   - `parseableItem = Boolean(item.id) || KNOWN_FIELDS.some(k => item[k] !== undefined)`
   - `validItem = !item.rawBlock && (!item.errors || item.errors.length === 0)`
6. 任何 API 捕获 `WorkspaceReadError` → 500 JSON `{error:"数据文件读取失败", code:"WORKSPACE_READ_FAILED"}`，
   不得继续写；日志保留绝对路径。
7. 后台循环（scheduler、caldav status/auto-sync）必须捕获 `WorkspaceReadError` 并记录一次事件，
   不得让未处理 rejection 退出进程。

### 2.2 唯一写入口

```ts
export interface MutateOptions {
  filePath?: string;
  /** changed=只校验新增/修改条目（默认）；all=整文件；false=跳过（仅导入/测试） */
  validate?: "changed" | "all" | false;
  timeoutMs?: number;
}

export async function mutateWorkspace<T>(
  fn: (ws: WorkspaceFile) => T | Promise<T>,
  opts?: MutateOptions,
): Promise<{ result: T; filePath: string }>;

/** 用于 WebDAV merge：在同一个锁事务内写调用方给出的完整文本 */
export async function mutateWorkspaceText<T>(
  fn: (ws: WorkspaceFile) => { result: T; text: string },
  opts?: MutateOptions,
): Promise<{ result: T; filePath: string }>;
```

流程：

1. `withWorkspaceLock`（默认 10s；排队超时 → `LockTimeoutError`，503；**超时的排队任务必须取消/移出队列，不得稍后执行**）。
   维护/只读检查在拿到锁之后再做一次：`isSyncMaintenance()` → `SyncEpochError` 503；
   `storageReadOnly` → `WorkspaceReadOnlyError` 503。这样恢复开始前已排队、恢复完成后才拿到锁的写不会落盘。
2. 锁内 `readWorkspace`（最新快照）。
3. 记录 `before = fingerprintItems(ws.items)`；`const result = await fn(ws)`。
4. 计算 `changedIds`：新增/删除/字段变化/`rawBlock` 变化；默认只对这些条目做图校验
   （见 2.6）。历史脏条目不参与，除非它被修改或它的 id 与新条目冲突。
5. `serializeWorkspace(...)` 或 `text`（`mutateWorkspaceText`）；先用 tolerant parse 验证：
   - 文件为空、无 `## ` 块、或只剩 notes/未知块 → **允许**（支持删除最后一条）；
   - 含 `## ` 块但零条可解析 → 抛 `WorkspaceReadError`（与 2.1 一致），不写；
   - 新增/修改条目通过图校验；历史坏块未被修改时原样保留；
   失败 → 不写。
6. 写前 `backupCurrent`（见 4.1）；普通写入备份失败仅告警；**restore 的 pre-restore 备份失败 fatal**。
7. `atomicWriteFile(filePath, content)`；返回。

`writeWorkspace` 改为 **不导出**（或 `/** @internal */` 仅测试）；所有调用方迁移：

| 调用点 | 改为 |
| ------ | ---- |
| `routes/workspace.ts:298/398/446/651/813` | `await mutateWorkspace`，领域错误用 `WorkspaceHttpError` |
| `caldav-sync.ts:950` | pull commit 的 `mutateWorkspace`，commit 前校验 epoch |
| `routes/webdav.ts:422` | `mutateWorkspace` 整体替换，备份由 store 做 |
| `routes/webdav.ts:505` | `commitMerge`（内部 `mutateWorkspaceText`），不嵌套锁 |
| `md-bridge.ts` / `kanban.ts` | 全部下线（D29），ICS 导出迁到 workspace 路由 |
| `config.ts:484` | `atomicWriteFile`（配置独立，不加 workspace 锁） |
| `scheduler.ts:70` / sync-state | `atomicWriteFile` + epoch/维护检查 |

### 2.3 锁

```ts
export function withWorkspaceLock<T>(fn: () => Promise<T>, timeoutMs = 10_000): Promise<T>;
```

- 进程内 Promise 队列（FIFO）；`tail = tail.then(run, run)`。
- 排队等待超过 timeout → `LockTimeoutError`（503）；**从队列移除/标记 canceled，绝不允许超时后仍执行**；已开始执行不强制中断。
- 队列项在 timeout 与轮到执行之间必须原子地二选一：执行或取消；测试覆盖“客户端 503 后任务不再写盘”。
- 重入：`AsyncLocalStorage<boolean>` 检测；重入直接 throw `LockReentryError`（500/编程错误），
  **不允许**在锁内再调 `mutateWorkspace`。需要同事务写原始文本时用 `mutateWorkspaceText`。
- 不跨进程；`DEV_RULES`/文档写明「不要多实例写同一文件」。
- 锁只包「读-改-写」；**网络 IO 在锁外**。

### 2.4 原子写与存储自检

```ts
export function atomicWriteFile(filePath: string, content: string): void;
export function verifyStorageSafety(dir: string): { ok: boolean; error?: string };
```

`atomicWriteFile`：

1. `tmp = `${filePath}.tmp.${process.pid}.${randomBytes(6).toString("hex")}`；`open(tmp,"wx",0o600)`。
2. `writeFile` → `fsync(fd)` → `close`。
3. `rename(tmp, filePath)`；Windows `EPERM/EBUSY/EACCES` 重试 5 次
   （100/200/400/800/1600ms）；仍失败 throw，**不降级直写**。
4. POSIX `fsync(dirname)` best-effort；失败仅告警。
5. 异常删除 tmp；启动清理本 pid 且 >1h 的 tmp。

`verifyStorageSafety`：

- 写 `.<basename>.write-test-<pid>-<rand>` → fsync → rename → 读回比较 → 删除。
- 返回 `{ok,error}`，不直接 exit。
- 启动顺序：**先 `resolveApiToken()`，再 `verifyStorageSafety()`**（token 写失败也能打印一次）。
- 失败且 `ALLOW_UNSAFE_FS !== "1"`：日志 ERROR，`storageReadOnly=true`，继续启动；
  所有 mutating API 返回 503 `{code:"WORKSPACE_READ_ONLY"}`；读/健康/备份列表可用。
- `storageReadOnly` 必须下沉到 store/sync-control：`mutateWorkspace`/`mutateWorkspaceText`、
  `writeSyncState`、reminder state 写入都拒绝；启动时 `startCalDAVAutoSync()` 与
  `startReminderScheduler()` 直接跳过（日志说明），避免周期性写失败/推送后落盘失败。
  备份 `preview` 需要写 `.pinned`：只读模式下返回 `pinned:false` + diff/sha，并提示无法恢复。
- `ALLOW_UNSAFE_FS=1`：日志 WARN，按可写继续（用户明确承担风险）。
- `/api/workspace/info` 返回 `storageSafe:boolean`、`readOnly:boolean`。
- D28：只读 `/data` 不再 `exit(1)`；见 decision-log。

### 2.5 解析/序列化 round-trip

```ts
export interface ExtraField { key: string; value: string; line: number }
export interface ParsedItem extends WorkbenchItem {
  extra?: ExtraField[];
  errors?: string[];
  /** 解析失败条目的原始块（写回原样保留） */
  rawBlock?: string;
}
```

规则：

1. 未知 `- key: value` 收进 `extra`；序列化在已知字段后按 `line` 顺序写回。
2. **frontmatter 保留原文**：`frontmatterRaw` 原样写回，不解析成 `Record<string,string>`，
   不把 `schema: workbench/v2` 降级；新文件才写默认 `schema: workbench/v1`。
   未知键、列表、嵌套、注释、空行均不丢失。v0.3 不提供 frontmatter 编辑 API。
3. 未知块：序列化为
   ```
   <!-- workbench:unknown:start -->
   ...原文...
   <!-- workbench:unknown:end -->
   ```
   放在 notes 之后；解析器识别该标记并存入 `unknownBlocks`，**不吞进 notes**。
   未知块内若含标记行，按第一次闭合处理并在测试中记录限制。
4. 解析失败/字段错误条目：保留 `rawBlock`，未修改时写回原样输出；不让它阻塞其他条目。
   若该条目被修改且仍有 `errors`（例如非法 `due`），`serializeWorkspace` 抛
   `WorkspaceValidationError`，不得静默丢掉错误字段；调用方必须显式修复或先删除。
   仅 `errors.length>0` 但未修改的条目保持 rawBlock，普通无关写入不会重写它。
5. 标量转义：`escapeScalar` 先 `\\` → `\\\\`，再 `\n` → `\\n`、`\r` → `\\r`；
   `unescapeScalar` 逆序。`title` 写入 `## ${escapeScalar(title)}`，`description/location/...`
   写入 `- key: ${escapeScalar(value)}`。解析时还原；字面 `\n` 与转义换行可区分。
6. 幂等：`parse(serialize(x))` 与 `serialize(parse(serialize(x)))` 结构相等；
   测试未知字段集合、unknown 块、frontmatter 原文、title/description 换行。

顺序：条目仍按现有 `sortItems` 规范化，不承诺原文件顺序。

### 2.6 图校验

```ts
export interface GraphIssue { code: string; itemId?: string; message: string }
export function validateWorkspaceGraph(
  items: ParsedItem[],
  opts?: { onlyIds?: Set<string>; includeHistorical?: boolean },
): GraphIssue[];
```

- 默认 `onlyIds`：只检查新增/修改条目参与的规则；`includeHistorical=true` 才整文件检查。
- 规则：id 唯一（仅当冲突一方在 onlyIds）；parent 存在（仅检查被改条目）；无自环/环；
  `end > start`（仅被改条目）；`remind` 可解析。
- 删除父条目时，把被删除 id 纳入检查：若仍有子条目 parent 指向它且未被级联删除，
  报 `ORPHAN_CHILD`（UI 现有级联删除应同时删子树；直接调用 store 的调用方必须处理）。
- 历史脏条目不参与，故一条旧脏数据不会让所有写入 400；用户可新建无关条目。
- `mutateWorkspace` 默认 `validate:"changed"`；`validate:"all"` 仅导入/显式修复；
  `validate:false` 仅测试。
- 失败 → 400 `{code:"WORKSPACE_INVALID", issues:[{code,itemId,message}]}`，不写。
- **远端数据**（CalDAV/WebDAV pull）逐条预校验：坏对象跳过 + `recordSyncEvent("error")`，
  不因单个坏对象 abort 整轮；仅结构性损坏（无法解析文本/全部坏）才 abort。

### 2.7 同步改造（prepare/commit）

新增 `sync-control.ts`：

```ts
export function currentSyncEpoch(): number;
export function invalidateSyncEpoch(): number;   // epoch++，返回新值
export function setSyncMaintenance(on: boolean): void;
export function isSyncMaintenance(): boolean;
/** WebDAV 等非 CalDAV 同步也登记；返回 end()，必须在 finally 调用 */
export function beginSyncActivity(kind: "caldav" | "webdav" | "restore"): () => void;
export function waitForInFlightSync(timeoutMs: number): Promise<boolean>; // CalDAV + WebDAV
```

- `caldav-sync.ts` 的私有 `inFlight` 由该模块登记；`stopCalDAVAutoSync()` 仍只清 interval。
- **WebDAV pull/merge 也登记 in-flight**：路由在开始网络请求前 `const end = beginSyncActivity("webdav")`，
  `finally end()`；`waitForInFlightSync` 等待 CalDAV + WebDAV 全部结束。恢复 drain 不再漏掉 WebDAV。
- 每个 sync 开始时 `const epoch = currentSyncEpoch()`。
- **每次** `mutateWorkspace`/`mutateWorkspaceText` 提交前、**每次** `writeSyncState` 前：
  `if (epoch !== currentSyncEpoch() || isSyncMaintenance()) throw new SyncEpochError()`；
  不写、记录 `epoch-aborted` 事件。手动 sync 入口也检查 `sync-suspended.json`/maintenance。
- store 在拿到 workspace 锁后还会再检查 `isSyncMaintenance()`（见 2.2）：即使恢复开始前请求已排队，
  恢复完成后也不能把旧数据写回。

**CalDAV pull**：

1. 锁外：登录/列远端/GET 变化对象 → `remoteChanges`；逐条 validateItem，坏对象跳过 + 事件。
2. 锁内 `mutateWorkspace`：基于最新 items + known 状态合并，只写变化条目；commit 前检查 epoch。
3. 锁外：`writeSyncState`（epoch 检查）并记录事件。

**CalDAV push**：

1. 锁内：读取待推送条目快照 + 字段指纹 + etag；释放。
2. 锁外：逐条 `PUT`（If-Match，若 etag 未知则不发送 If-Match）。
3. PUT 成功后：若响应有 ETag 用它；没有则标记 `etag:null`（下一轮先 GET/无条件 PUT 收敛），
   **不得**保留旧 etag 导致永久 412。
4. 锁内：复核指纹；变化 → 标记 `pending`，**不覆盖远端**（PUT 已发出，无法回滚；
   语义对齐 plan A-C3：下一轮 If-Match 收敛），记录冲突事件。
5. 412 → 记冲突（409 给 UI），本地不变。

**WebDAV pull**：`beginSyncActivity("webdav")`；下载远端文本（锁外）→ 解析/逐条校验 →
`mutateWorkspace` 整体替换；全部不可解析则 abort 并保留本地；备份由 store 做；`finally end()`。
若 restore 在下载期间开始，`mutateWorkspace` 在锁后看到 maintenance 直接 503，不落本地。

**WebDAV merge**（D27）：

```ts
prepareMerge(remoteText, remoteEtag):
  withWorkspaceLock:
    const ws = readWorkspace();                 // 同一快照
    const baseHash = sha256(ws.raw);
    const merged = mergeWorkspaceFile(ws, parseWorkspace(remoteText)); // 保留元数据
    const issues = validateWorkspaceGraph(merged.items, {includeHistorical:true});
    if (issues.length) throw new MergeInvalid(409, issues); // PUT 之前失败，远端不动
    return { baseHash, mergedText: serializeWorkspace(merged), summary, remoteHash };
  // 锁释放，网络 IO 在锁外

commitMerge({baseHash, mergedText, remoteEtag, remoteHash}):
  mutateWorkspaceText((ws) => {
    if (sha256(ws.raw) !== baseHash)
      throw new MergeConflict(409, {remoteEtag, localHash: sha256(ws.raw)});
    return {result: summary, text: mergedText};
  });
```

1. 路由整体包在 `beginSyncActivity("webdav")` 中；restore 的 drain 会等待它结束。
2. 下载远端 → `prepareMerge`（锁内取 baseHash，用同一 `ws.raw` 合并并**先校验**）；释放。
3. 锁外 `PUT`（If-Match）；412 → 本地不动，原样返回，**不 commit**。
4. PUT 成功后 `commitMerge`：
   - baseHash 未变且非 maintenance → 写本地 mergedText；
   - baseHash 已变 → **不写本地**，409 `{error:"远端已写入合并版；本地保留你的新改动，请重新合并", remoteEtag, localHash}`；
   - maintenance/epoch 失效 → 不写本地，503 `SYNC_EPOCH_ABORTED`，并记录冲突事件
     `{remoteEtag, remoteHash}`；远端已是合并版，UI 只提供「重新合并」。
5. **合并文本 parse/图校验失败必须发生在 PUT 之前** → 409 `MERGE_INVALID`，本地不动、远端不动。
6. `mergeWorkspaceFile(local, remote)` 的三方保留规则：
   - `frontmatterRaw`：本地优先；若远端 `schema` 版本更高则用远端，绝不把 v2 降级为 v1；
   - `unknownBlocks`：本地块在前，追加远端独有块（按规范化文本去重）；
   - items：按 `id`/`uid` 并集，同 id 取 `updatedAt` 较新者，相同/冲突保留本地；
     远端独有坏条目连同 `rawBlock` 保留；
   - item 的 `extra`：并集，本地键优先；`rawBlock`：本地优先，远端独有保留。
   `serializeWorkspace` 必须接受含 `frontmatterRaw/unknownBlocks/extra/rawBlock` 的 `WorkspaceFile`。
7. 禁止在 `withWorkspaceLock` 内调 `mutateWorkspace`；`commitMerge` 内只调用一次 `mutateWorkspaceText`。
8. PUT 后 commit 失败不得显示「本地/远端均未变」；必须返回 `remoteEtag + remoteHash` 并要求重新合并。
9. S12 覆盖：远端正文字段/未知块/坏条目、本地未知块、v2 frontmatter、PUT 后 commit 失败。

## 3. 认证（M4）

### 3.1 token 生命周期

```ts
export class ApiTokenError extends Error { ... }
export function resolveApiToken(): {
  token: string; source: "env"|"file"|"generated"; tokenFile: string; persisted: boolean;
};
```

- 顺序：`process.env.API_TOKEN`（trim 后非空）→ `API_TOKEN_FILE` 或
  `${dataDir}/api-token.txt` → 生成 `crypto.randomBytes(32).toString("hex")`。
- **校验规则（两条通道不同）**：
  - env token：trim 后必须匹配 `^\S{32,}$`（≥32 个非空白字符，允许任意可见字符）；
    空串/纯空白/含空白/过短 → `ApiTokenError`，拒绝启动并提示设置合法 `API_TOKEN`。
  - 文件 token：trim 后必须匹配 `/^[0-9a-f]{64}$/`；空文件、仅换行、截断 hex、乱码 → 损坏。
  - 损坏文件：可写 → rename 为 `api-token.invalid-<ts>`，原子写新 token；
    不可写 → **生成内存 token，`persisted:false`，启动日志打印一次并强告警**，
    不因只读 `/data` 拒绝启动；重启后 token 变化，文档要求设置 `API_TOKEN`。
- 文件不存在：生成新 token；可写则原子写 0600，不可写则内存 token + 打印一次。
- 写文件：`atomicWriteFile` + `fchmod(0o600)`；已存在 0644 时尝试 chmod 0600，失败 WARN。
- 日志：正常只打印 `tokenFile` 路径，不打印 token（`persisted:false` 的一次性打印除外）。
- 轮换：改 env / 删文件重启；浏览器重新输入。
- 比较：**双方先 `sha256` 得到 32 字节**，用 `timingSafeEqual` 比较；token 与 candidate
  都必须非空，candidate 不要求 64 hex（env token 可以是任意 ≥32 可见字符）。
  空 candidate 直接 401，不进入比较。
- `createApp` 的 `auth` 必须显式：v0.2.5/测试传 `auth:false`，v0.3.0 传
  `auth:{token}`；`undefined`、`{token:""}`、`{token:"   "}` 一律 throw `ApiTokenError`，
  杜绝漏传导致 fail-open。

### 3.2 createApp 顺序

```ts
export interface CreateAppOptions {
  /** 必填：false 仅 v0.2.5/测试；{token} 为 v0.3.0。undefined 视为配置错误 */
  auth: false | { token: string };
  staticDir?: string;
  trustProxyHops?: number;
  storageReadOnly?: boolean;
}
export function createApp(opts: CreateAppOptions): express.Express;
```

顺序（必须一致）：

1. `app.set("trust proxy", hops)`（hops=0 不信任 XFF）。
2. `app.use(cors(corsOptions))` —— `OPTIONS` 由 cors 结束（204）。
3. `app.get("/health", ...)`。
4. `app.use(canonicalizeApiPath)`：在 auth/static 之前规范化路径。
   - 对 pathname 做一次 `decodeURIComponent`；非法编码 → 400 `BAD_PATH`；
   - 若解码后（大小写不敏感）以 `/api` 开头但原始 pathname 不是 `/api` 前缀
     （典型 `/%61pi/...`）→ 400 `ENCODED_API_PATH`，不能落到 static/SPA；
   - 原始路径含 `%2f`/`%5c`（编码斜杠/反斜杠）→ 400，防止路径段折叠；
   - 通过后把 `req.url` 保留原样（Express 后续按原始 pathname 路由），
     但确保所有 `/api` 分支已被 auth/API 404 覆盖。
5. `app.use("/api", authMiddleware)`；`opts.auth === false` 时跳过（仅 v0.2.5/测试）。
6. `app.use(express.json({ limit: "1mb" }))`（auth 之后）。
7. `app.use("/api", readOnlyGuard)`：`storageReadOnly` 时除只读白名单外，所有
   POST/PUT/PATCH/DELETE → 503 `WORKSPACE_READ_ONLY`；白名单：
   `GET/HEAD /api/*`、`POST /api/workspace/backups/preview`（返回 `pinned:false`）、
   `POST /api/workspace/backups/restore/abort`。
8. `app.use("/api", maintenanceGuard)`：恢复窗口内除 allowlist 外 503 `MAINTENANCE`；allowlist：
   `GET /api/workspace/backups`、`POST /api/workspace/backups/preview`、
   `GET /api/workspace/backups/export`、`GET /api/workspace/backups/restore/status`、
   `POST /api/workspace/backups/restore`（重试）、`POST /api/workspace/backups/restore/abort`、
   `GET /api/sync/overview`、`GET /api/workspace/info`、`GET /health`。
9. 所有 API 路由（workspace/webdav/nlp/config/plugins/caldav/notifications/backups/sync）。
10. `app.use("/api", apiNotFound)` → 404 JSON；必须在 static 之前，防止
    `staticDir/api/*` 被公开，也保证未知 `/api/foo` 不是 HTML。
11. `app.use(express.static(staticDir, {index:false, fallthrough:true, ...}))`；
    静态目录显式 deny `api/` 前缀（双保险）。
12. SPA fallback：仅 `GET/HEAD`，且路径不匹配 `/^\/api(\/|$)/i`、`/health`、`/assets/`、
    `sw.js`、`workbox-`、`manifest.json`；`index.html` 不存在则跳过。
13. 404 JSON `{error:"Not found"}`。
14. 4 参错误中间件（最后）：`entity.parse.failed` → 400；`WorkspaceReadError` → 500；
    `WorkspaceValidationError`/`MergeInvalid` → 400；`WorkspaceHttpError` → 其 status；
    `LockTimeoutError` → 503；`WorkspaceReadOnlyError` → 503；`SyncEpochError` → 503。
    500 响应不含绝对路径。

注意：`/API`、`/Api` 由 Express 大小写不敏感匹配 `/api`，先经过 auth；
`/%61pi/...` 由第 4 步 400；`/api//` 经过 auth 后由 API 404 JSON 处理。
测试覆盖 `/%61pi/workspace/items`（400）、`/%2fapi/...`（400）、`/API/...`（401）、
`/api//...`（401/404 JSON）、static 下 `api/x`（404 JSON，不是文件）。

### 3.3 CORS / 代理

- `corsOptions.origin`：
  - 无 `Origin`（curl/同源 GET）→ 允许；
  - `Origin` host 与 `req.headers.host` 相同 → 允许；
  - `CORS_ORIGINS` 逗号分隔精确匹配 → 允许；

- `TRUST_PROXY_HOPS`：整数；`app.set("trust proxy", n)`；n>0 启动 WARN。
- 不实现限流（v0.3.1）。

## 4. 备份与恢复

### 4.1 文件布局

```
data/
├── workspace.md
├── .workspace-backups/
│   ├── workspace-2026-11-02T10-00-00-000Z.md
│   ├── .pinned/<sha256>.md
│   └── .pre-restore/workspace-<ts>.md
├── .caldav-sync-state.json
├── .webdav-state.json
├── .reminder-state.json
├── restore-in-progress.json
└── sync-suspended.json
```

- 自动备份：写前复制；文件名 `workspace-<ISO>-<rand6>.md`（避免同毫秒碰撞）；
  最多 20 份 / 50MB（按文件名内的时间戳倒序删旧，不依赖 mtime）；`MAX_BACKUPS` 从 10 改 20，测试同毫秒两次写。
  已固定的快照（`.pinned/<sha>.md`）在固定期内不参与轮转删除。
- `pre-restore` 最多 5 份，不参与自动轮转。
- `.pinned` 24h 清理；预览时复制，避免轮转删除。
- 备份文件列表使用 tolerant parse；不得因单个坏备份让整个列表 500。

### 4.2 API（M3a 只读）

`GET /api/workspace/backups`

```json
{ "success": true, "backups": [
  { "file": "workspace-....md", "createdAt": "...", "size": 1234, "itemCount": 42,
    "pinned": false, "pinnedSha256": null }
] }
```

- `itemCount` 用 tolerant parse；无法解析 → `null`，不抛 500。
- 已 pin 的备份返回 `pinnedSha256`，供 restore 使用。

`POST /api/workspace/backups/preview` `{ "file": "workspace-....md" }`

```json
{ "success": true, "file": "...", "sha256": "...", "diff": {
  "added": 3, "removed": 1, "changed": 2,
  "items": [{ "id": "...", "title": "...", "change": "added|removed|changed", "fields": ["due"] }]
}}
```

- `file` 必须 `path.basename(file) === file`；`realpath` 必须在备份目录内；否则 400。
- 读取同一 Buffer 计算 sha，再复制到 `.pinned/<sha256>.md`（先写 tmp 再 rename）；
  返回 sha；预览不写 workspace。恢复窗口内 preview 在 allowlist 中可执行（只写 `.pinned`）。
- 只读 `/data`：preview 仍计算 diff/sha，但不 pin（`pinned:false`），提示「无法固定快照，恢复不可用」。
- 预览后 24h pinned 被清理；restore 时若缺失 → 409 `RESTORE_SNAPSHOT_EXPIRED`；
  UI 此时可重新预览或 abort。

`GET /api/workspace/backups/export?file=...` → `text/markdown` 附件（同样 basename/realpath 校验）。

### 4.3 恢复（M3b，需 token）

`POST /api/workspace/backups/restore` `{ "file": "...", "sha256": "...", "confirm": true }`

状态机：

1. 校验 `confirm === true`、file/sha 格式、token；获取 **restore mutex**；
   第二个并发 restore → 409 `RESTORE_IN_PROGRESS`。
2. 写 `restore-in-progress.json` `{epoch: Date.now(), file, sha256, phase:"starting"}`（原子写）。
3. `setSyncMaintenance(true)`；`stopCalDAVAutoSync()`；`invalidateSyncEpoch()`；
   `await pauseReminderScheduler()`（停 timer 并等待当前 tick 结束，防止 sent 写回）。
4. `waitForInFlightSync(10_000)`（CalDAV + 已登记的 WebDAV pull/merge）；超时 → 保留 marker，
   返回 503 `RESTORE_DRAIN_TIMEOUT`，maintenance 保持 true；不得继续覆盖。
5. `withWorkspaceLock`：
   - 读 pinned 文件同一 Buffer，校验 sha；缺失/已过期 → 409 `RESTORE_SNAPSHOT_EXPIRED`；
   - 解析 pinned 内容 + `validateWorkspaceGraph(..., {includeHistorical:true})`；失败 → 400
     `RESTORE_INVALID_SNAPSHOT`，本地不动；
   - **pre-restore 备份当前 workspace；失败 → 500 `RESTORE_BACKUP_FAILED`，abort，保留 marker**；
   - 先把 `.caldav-sync-state.json`/`.webdav-state.json` rename 为 `.pre-restore-<ts>`，
     再写空 state（`{version:1, objects:{}}`）；任一步失败 → 500 `RESTORE_STATE_FAILED`，
     不覆盖 workspace，保留 marker/maintenance；
   - `atomicWriteFile` 写 pinned 内容；
   - 重置 `.reminder-state.json`：sent 保留 `id|remind` 交集，failed 清空；写入失败 →
     500 `RESTORE_STATE_FAILED`，marker/maintenance 保留（workspace 已是恢复版，可重试或 abort）；
   - `sync-suspended.json` 写入 `{reason:"restore", at, epoch}`；失败 → 500，不 clear marker。
6. 清 marker；`setSyncMaintenance(false)`；`resumeReminderScheduler()`；释放 mutex；返回
   `{success, diff, autoSyncPaused:true}`。

- **maintenance 覆盖所有 mutating `/api`**（POST/PUT/PATCH/DELETE），除 allowlist 外返回 503
  `MAINTENANCE`；allowlist：备份列表、preview、export、restore/status、restore（重试）、
  restore/abort、sync overview、workspace info、health。普通写不能在恢复窗口落地。
- **preview 必须可用**：恢复窗口内允许 `POST /api/workspace/backups/preview`（只写 `.pinned`），
  否则 pinned 过期后用户无法重新预览。
- **sync-suspended 硬拦**：CalDAV 自动/手动 sync、WebDAV pull/merge 入口都检查；
  手动 `POST /api/caldav/sync` 返回 409 `SYNC_SUSPENDED`。
- **epoch 检查点**：sync 取远端后、进入每个 commit 前、每次 `writeSyncState` 前；
  reminder tick 写 state 前也检查 maintenance/epoch。
- 恢复完成不自动同步；用户通过 `POST /api/sync/resume`
  `{action:"pull"|"push"|"bidirectional"}` 清 suspend，并由 UI 触发对应同步；
  `bidirectional` 对应 CalDAV 双向；WebDAV 冲突仍走 merge UI。resume 后若配置了自动同步，
  重新 `startCalDAVAutoSync()`（不是恢复时自动跑）。
- **恢复失败/中断的逃生路径**：
  - 启动时若存在 marker 且 pinned 存在且未过期：不自动恢复；`maintenance=true`；
    暂停自动同步/reminder；overview `restorePending:true`；提供「重试」「取消恢复」。
  - 启动时若 marker 存在但 pinned 缺失/过期：**自动清 marker、maintenance=false**，
    保留 `sync-suspended.json` 和 `.pre-restore-*`，记录 `RESTORE_ABANDONED` 事件，
    UI 显示「上次恢复未完成，已保留当前文件；可查看备份/恢复或继续使用」。
    不允许永久锁死，也不静默覆盖。
  - `POST /api/workspace/backups/restore/abort` `{confirm:true}`：需 token；restore mutex
    正在执行 → 409 `RESTORE_IN_PROGRESS`；否则清 marker、`setSyncMaintenance(false)`、
    `resumeReminderScheduler()`，**保留** `.pre-restore-*` 与 `sync-suspended.json`，
    返回 `{success, autoSyncPaused:true}`。UI 在 409/超时/启动 pending 时提供「取消恢复，
    保留当前文件」。
  - abort 后 sync 仍 suspended；用户需 `/api/sync/resume` 选择方向。
  - 崩溃阶段（写 marker 后/等待中/覆盖后状态重置前/清 marker 前）都可通过 marker + 重试恢复。

### 4.4 UI（设置 → 数据）

- 备份列表：时间/大小/条目数（`null` 显示「无法解析」）/「预览」「导出」。
- 恢复 pending / 409/超时：显示「重试」「取消恢复（保留当前文件）」；取消后提示自动同步仍暂停，
  需在同步中心选择方向。
- 预览：`+3 新增 / -1 删除 / ~2 修改` + 前 20 条标题；「恢复」按钮（v0.3.0，需 token）。
- 恢复确认：输入 `RESTORE` 或勾选；文案「只改本地文件，云端/手机不会自动变；下次同步可能冲突」。
- 500 页/ErrorBoundary：链接本页 + 手动恢复 3 步（下载备份 → 覆盖 `data/workspace.md` → 重启）。
- 关于/数据页：版本、数据路径、备份数、`/health`、`storageSafe/readOnly`。

## 11. 风险与开放问题

1. **编码路径绕过**：Express 4 的 `app.use("/api")` 匹配未解码 `req.url`；必须先
   `canonicalizeApiPath`，拒绝 `%61pi`/`%2f`/`%5c` 并返回 400，再进 auth/static；
   S7/S16 覆盖。SPA 另排除 `/^\/api(\/|$)/i`。
2. **Electron 端口竞争**：取空闲端口后 close 再 fork 存在 TOCTOU；失败重试 3 次，UI 提示。
3. **Windows rename**：杀软/索引器；随机 tmp + 5 次重试 + 报错；发布前 Windows 冒烟。
4. **9p/SMB**：自检可能误判；默认只读降级，`ALLOW_UNSAFE_FS=1` 逃生；文档写清。
5. **恢复中断/无出口**：marker/epoch 覆盖「覆盖后、状态重置前」；preview 必须被
   maintenance 放行；pinned 过期/损坏/drain 超时可用 abort；启动自动清过期 marker；S18 注入。
6. **备份轮转**：pinned 复制 + sha；S9 覆盖轮转删除/过期。
7. **Electron 打包**：esbuild 单文件 + extraResources；P6 必须安装包冒烟；native 依赖若出现再评估。
8. **i18n**：新增 key 必须 zh/en 同步，parity 测试会失败。
9. **M5 不联网**：禁止调用 `/api/webdav/status`；用 state/config；plan 字段表已删 `remoteChanged`。
10. **pnpm 11.8 + lockfile 9**：M1 第一天跑 `--frozen-lockfile`；失败则 pin 兼容版本。
11. **D19 扩大**：md-bridge/kanban 全下线可能影响外部脚本；README/升级说明给出替代 API。
12. **token 只读**：无法持久化时每次重启 token 变；文档要求设置 `API_TOKEN`。
13. **WebDAV 在飞**：恢复只等 CalDAV 会漏 WebDAV pull/merge；统一注册
    `beginSyncActivity("webdav")`，恢复等待两者，提交前再查 epoch/maintenance。
14. **reminder 跨恢复**：scheduler tick 必须注册 activity 并在写 sent 前查 epoch/maintenance，
    否则会把旧 sent 写回；S10/S18 覆盖。
15. **锁排队超时**：请求 503 后排队任务不得稍后执行；超时即从队列移除，只允许运行中的 fn 跑完。
16. **合并元数据**：WebDAV 三方合并必须保留 frontmatter/unknown/extra/rawBlock；
    PUT 后 commit 失败要记录冲突/remoteEtag/remoteHash，不能假装成功。
17. **只读启动**：除 `mutateWorkspace` 外，config/restore/state 写也必须 503；
    auto-sync/reminder 不启动。
