# v0.4 实施计划（草案）

> **状态**：草案，依据 `v0.4-product-decisions.md`（D36–D42）推导；**尚未评审**。
> **性质**：实施路线图，列出 PR 序列、每个 PR 的可失败测试、验收标准与依赖。计划阶段不写代码。
> **当前代码基线**（2026-11-20 实查）：v0.3.1，server 446 测试 / renderer 115 测试全绿；`FullCalendar` 位于 `apps/renderer/src/components/Calendar.tsx`，当前 `editable={false}`、无 `eventDrop`/`eventResize` 处理器；重复例外 `recurrenceId` 字段在 ICS 导入侧仅做「跳过」，无写回路径；`ai-agent` 是唯一活跃占位（`git-sync` 已被同步中心替换，仅文档残留）；无内存索引层。

## 0. 规划原则

1. **成熟度版本，不是功能堆积**（D42）。每个 PR 必须有可失败的测试先行。
2. **数据层物理形态不变**（D39）：v0.4 单文件；只加派生索引接口，不引入 SQLite / 多文件。
3. **本地优先不退化**（D37）：任何同步改动不得让离线读写变慢或依赖网络。
4. **正确性优先于性能**（D39）：先稳定全量解析 + 索引，再谈增量。
5. **依赖准入**（oss-reuse-audit.md D35）：新增依赖需 MIT/ISC/BSD/Apache、纯 JS、Node 22、体积达标。cmdk 已核验 MIT ✅。

### 阶段 B — 领域数据派生索引（D39 预留能力）

**PR-B1 内存索引层（只读派生）**
- 代码：新增 `apps/server/src/workspace-index.ts`：`buildIndex(ws)` 产出 `{ byId: Map, byList: Map, byDate: Map }` + `rawBlockRanges`；`query` 走索引，写入后增量更新（先全量重建，测性能后再优化）。

## 2. 依赖关系与发布节奏


- B2 接口定义可与 A 并行，但 B1 的索引是 A1/A4 快速定位的前置。

## 3. 每个 PR 的 Definition of Done（沿用全局 System Prompt）

1. 目标达成（PR 描述的功能可用）。
2. 符合 `v0.4-product-decisions.md` 约束（本地优先/单一事实源/冲突不静默覆盖）。
3. 测试实际跑过（server + renderer + e2e，数字写进 `docs/TESTING.md`）。
4. 独立 reviewer 审关键改动（A2 重复语义、C1 墓碑、B1 索引一致性必须审）；Critical/High 全关闭。
5. 无隐瞒 blocker。
6. 文档更新（`MODULE_STATUS.md` / `UPDATE_LOG.md` / README 状态）。
7. 可交付（build 通过、无 localhost 泄漏）。
8. 限制列明（如「Radicale 真机待用户服务器」、「GUI 冒烟待用户本机」）。
