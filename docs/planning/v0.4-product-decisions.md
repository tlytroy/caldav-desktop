# v0.4 产品与架构决策（定稿）

> **状态**：用户裁决，2026-11-20（回答 Harness 的 6 个方向问题）。
> **性质**：这是 v0.4 的**约束文件**，不是实施计划。它回答「做什么、不做什么、按什么优先级」，实施计划另见 `v0.4-implementation-plan.md`。
> **定位一句话**：**Desktop-first · Local-first · Markdown-native · Sync-optional**。
> **核心原则（不可妥协）**：`workspace.md` 唯一事实源；离线可用；同步永不破坏本地数据；冲突不静默覆盖。

## 1. 六项决策

### D36 — 主用设备：Windows Electron 桌面优先

| 平台 | 定位 | 优先级 |
| --- | --- | --- |
| Windows Electron | 主力客户端 | P0 |
| Docker + 浏览器 | NAS 部署、跨设备访问 | P1 |
| PWA | 手机临时访问 | P2 |
| Android 原生 | 暂不开发 | P3 |

**不为 Android 在 v0.4 下沉整个领域数据层。** 但保持一条架构底线：领域模型 / Markdown Parser / Query Engine / 时间规则 / 同步逻辑尽量 UI 无关，避免 Electron / Web / PWA 各自出现一套业务逻辑。这是为了防止未来分裂，不是为现在做 Android。

### D37 — 部署重心：单机本地优先，NAS 是第二形态

明确定位：**ChronoMD 是 Local-first Desktop Productivity App；NAS 是可选的自托管部署形态，不是产品运行的中心服务器。**

推论（全部为硬约束）：
- 不引入强制账号体系。
- 不引入强制云端数据库。
- 不把在线状态作为日历/任务的前置条件。
- 不为多端实时协作引入 CRDT。
- 不让远端同步决定本地数据是否可读写。
- NAS 版不是简化版：它是完整的第二运行模式，提供长期提醒调度、远端访问和多设备共享。

### D38 — CalDAV 服务端：以 Radicale 建基线

Radicale 作为第一套轻量标准兼容测试环境。此前 OneDrive/SharePoint 风格网关的 ETag 双命名空间问题（已修）**单独保留为 WebDAV 回归用例**，不与 CalDAV 测试混在一起。CalDAV 真机测试等用户服务器起来后再做。

### D39 — 数据架构：唯一事实源长期坚持，物理形态暂不变

区分两个概念：
- **唯一事实源**：长期原则。
- **唯一物理文件**：当前实现选择，v0.4.5 spike 后再定。

v0.4 保持单文件；v0.4.5 做 Spike（原定两周）。**现在就预留**这些能力：

| 能力 | v0.4 实现 | 原因 |
| --- | --- | --- |
| 内存索引 | 是 | 避免每次查询全量扫描 |
| 增量解析接口 | 是（先定义接口） | 后续性能优化预留 |
| ID 索引 | 是 | 快速定位/更新条目 |
| 原文位置追踪 | 是 | 无损修改局部块 |
| Markdown 重建索引 | 是 | 索引必须可丢弃、可重建 |
| SQLite 持久化索引 | 否 | 等 Spike 决定 |
| 多文件 Vault | 否 | 不提前增加复杂度 |

**索引永远是派生数据，`workspace.md` 才是权威。** 关系链：`workspace.md`（唯一事实源）→ Parser + Domain Model（解析/校验/领域语义）→ Query Index（内存索引）→ UI Projections（日历/看板）。索引损坏可重建，视图可重新生成，都不允许反向成为事实源。

不要为增量解析牺牲正确性：**先做稳定的全量解析 + 索引，再用性能测试决定是否需要真增量解析。**

### D40 — v0.4 功能顺序

| 顺序 | 功能 | 归属 |
| --- | --- | --- |
| 1 | 日历拖拽改期 | v0.4 |
| 2 | 重复事件单次编辑 | v0.4（需独立规格+测试） |
| 3 | 命令面板（cmdk） | v0.4 |
| 4 | CalDAV 删除传播（墓碑） | 同步专项优先，不阻塞桌面交互发布 |
| 5 | 清单排序 / 颜色 / 拖拽 | 可与日历交互一起做 |
| 6 | ICS / Obsidian Tasks / Todoist 导入 | 分阶段：Obsidian Tasks → Todoist → ICS 增强 |
| 7 | git-sync / ai-agent 占位 | 删除假入口，真实实现时才加入 |

**重复事件单次编辑的语义清单**（必须单独规格+测试，不许把 FullCalendar 拖拽回调直接写进 Markdown）：修改整个系列 / 只改当前实例 / 改当前及未来实例 / RECURRENCE-ID / 删除单个重复实例。处理不好会直接造成 CalDAV 数据不一致。

**墓碑不能无限期拖**：属同步正确性问题，不是普通功能缺口；但归同步专项，不为它阻塞桌面交互发布。

### D41 — Electron GUI 冒烟由用户本机完成

Harness 无显示环境，不能声称已做 GUI 验证。最小验收标准：

| 检查项 | 验收标准 |
| --- | --- |
| 应用启动 | Electron 主进程正常启动 |
| 窗口显示 | 窗口正常显示，无白屏 |
| 前后端连接 | 随机端口 + token 注入正常 |
| 日历 | 能看到日历视图 |
| 任务 | 能看到任务列表 |
| 创建 | 新建一条任务或事件 |
| 持久化 | `workspace.md` 确实发生预期变化 |
| 重启 | 重启后新建条目仍存在 |

不为此引入复杂 GUI 自动化框架；出问题再补主进程日志 / Renderer 控制台 / 服务端日志。

### D42 — v0.4 是成熟度版本，不是功能堆积版本

不要因为看到别的开源项目有某功能就不断往产品里加。**重点保护三个核心特征：纯 Markdown、真正本地优先、同步不破坏数据。**

v0.4 重点：① 桌面交互效率 ② 重复事件语义正确性 ③ Markdown 数据可靠性 ④ 同步冲突与删除一致性。

## 2. 实施顺序（由上述决策推导）

```
阶段 A（桌面交互）  → 阶段 B（领域数据） → 阶段 C（同步正确性） → 阶段 D（导入/清理）
  拖拽改期                内存索引 + ID 索引     墓碑删除传播         Obsidian Tasks 导入
  重复事件单次编辑         原文位置追踪          Radicale 基线测试      Todoist 导入
  命令面板 cmdk           增量解析接口定义                           删除 git-sync/ai-agent 占位
  清单排序/颜色/拖拽
```

- 阶段 A 与阶段 B 可并行准备，但阶段 A 的功能若依赖索引（如拖拽后快速定位），先落 B 的最小索引。
- 阶段 C 不阻塞阶段 A 的发布；作为独立同步专项 PR 序列。
- 阶段 D 中 ICS 导入继续增强已有实现，不另起体系。

## 3. 明确不做（v0.4）

- Android 原生 / 为 Android 的大规模架构重构。
- SQLite 持久化索引 / 多文件 Vault（留 v0.4.5 Spike）。
- CRDT / 强制账号 / 强制云端数据库 / 把 NAS 变成中心服务。
- 对任何 GPL/AGPL/MPL/无许可证项目代码的引入（见 `docs/research/OPEN_SOURCE_RESEARCH.md`）。
- 假入口：git-sync / ai-agent 占位。
