# 独立评审 A（架构 / 安全 / 数据一致性）— v0.3 计划 v0.2

> 评审对象：`docs/planning/v0.3-plan-v0.2.md`
> 结论：**有条件通过**（方向与 D1–D15 一致；5 条必须先落到 SDS/计划）

## 1. 结论与 5 条必须条件

1. **认证落点**：必须 `app.use("/api", auth)` 且注册在所有 `/api` 路由之前；
   禁止 `req.path.startsWith("/api/")`（Express 路由大小写不敏感，`/API/workspace/items` 会命中
   workspaceRouter 却绕过前缀判断）。`/health`、静态资源、SPA 按非 `/api` 豁免。
2. **消除 D1 与 M3 矛盾**：不配 token 是「启动失败」还是「启动但全 401」只能选一个。
   建议「启动 + 全 401，Docker compose 强制非空」。
3. `readWorkspace` 读取失败必须 throw（`workspace.ts:465-470` 现在返回空 items，
   任何读改写会清空事实源）；`writeWorkspace` 收为私有，只暴露 `mutateWorkspace(fn)`；
   v0.3 关闭或限定 `/api/md-bridge` 的任意 `filePath` 写入（`routes/md-bridge.ts:88/149/187/314`）。
4. 恢复必须静默在飞同步：`stopCalDAVAutoSync` 只清 timer（`caldav-sync.ts:1054`），
   inFlight 仍会写 workspace（`:950`）；需要 epoch 丢弃旧结果 + 等 inFlight + 恢复后自动同步默认暂停。
5. M1 明确 server typecheck 处置（修约 150 个测试类型错误，或建独立 `tsconfig.test` 并登记欠账），
   否则「CI 全绿」是靠删检查换来的（`test.yml:42-50`），build 的 `tsconfig.build` 又排除了测试。

## 2. 阻塞问题

- **认证落点无法两全**：`index.ts` 中 `/api` 路由 33-54，静态 64-74，caldav/notifications 78/81。
  auth 放静态前 → SPA 加载 401，令牌页死锁；放静态后 → 33-54 裸奔。
  `express.json()`（:25）在 auth 前，未授权可消耗 JSON 解析。
  **建议**：`createApp()` 显式阶段：json(limit) → health → static → `/api` auth → 路由 → SPA 兜底；
  OPTIONS 由 cors 在 auth 前处理。
- **TRUST_PROXY_HOPS 测试是假测试**：token 不绑 IP，XFF 只影响限流/日志；
  验收 #3 无论实现对错都通过。真正风险是 hops>0 + 端口直暴时 proxy-addr 取到伪造值绕过 429，
  Docker bridge 下所有客户端同 IP。**建议**：hops 只影响 `req.ip`；hops>0 启动告警；
  限流表 LRU 上限。
- **Electron 路径**：`main.ts:14` fork 只传 PORT；`index.ts:97` `listen(PORT)` 绑 0.0.0.0；
  固定 3001 与 dev/多实例冲突；`main.ts:55` 先 loadFile 不等 server ready；
  `preload.ts:18` 只暴露空 `electron`；`base.ts:54` 模块加载期同步取 baseURL，`file://` 下相对路径
  变成 `file:///api`。**结论：只保留本地 HTTP 同源**——随机端口、HOST=127.0.0.1、等 `/health`、
  preload 在页面脚本前同步注入 `{baseUrl,token}`；异步 IPC 会牵动 11 个 axios 实例，M3 预算不够。
- **锁与同步改造不匹配现状**：CalDAV push 持快照逐条 PUT，锁内重读挡不住旧快照覆盖远端；
  WebDAV merge 先 PUT 远端再写本地（`webdav.ts:486-505`），localText 在网络调用前读取，
  中间失败即分叉。**建议**：prepare/commit + 锁内指纹复核 + 412 转 409；承认跨网络无法原子。
- **写路径没收敛**：`writeWorkspace` 仍 public，6 处调用（`routes/workspace.ts:298/398/446/651/813`、
  `caldav-sync.ts:950`）；另有 md-bridge 任意路径写、`kanban.ts:103/284`、`config.ts:484`
  （含 webhook secret）、`scheduler.ts:70`、两处 sync-state 裸 `writeFileSync`。
  md-bridge 让「唯一事实源」形同虚设。
- **恢复**：`.workspace-backups` 每次写都备份且只留 10 份（`workspace.ts:474-500`），
  预览后目标可能被轮转删除；`{file}` 未定义 basename/realpath 校验；WebDAV etag 重置后
  下一次 pull 会用远端整文件覆盖刚恢复的本地（`webdav.ts:397/422`）；
  D11「清空 sent」与验收 #9「旧提醒不重发」矛盾（应改为按 `id|remindAt` 保留）。
- **原子写现实**：Windows rename 会因 AV/索引器 EPERM/EBUSY，3 次 350ms 偏短；
  9p/SMB rename+fsync 语义弱。**建议**：启动自检写 tmp→fsync→rename→fsync dir，
  不支持则拒绝或强告警；文档写明数据目录必须本地 ext4/NTFS；stale tmp 只清理本 pid。
- **CI/工时**：`packageManager: pnpm@11.8.0` 与 lockfileVersion 9.0 是否匹配需验证；
  M2（解析器 extras + 6 处调用改造 + 并发/崩溃测试）实为 6–8 天，M3 3.5–4.5，M4 3–3.5，
  合计 17–22 天，12–18 只能靠砍范围。

## 3. SDS 必须定的点（建议默认）

1. Electron 只用本地 HTTP 同源 + 随机端口 + 同步注入；不做 file:// 双路径。
2. 唯一写入口 `mutateWorkspace`，10s 可取消队列、禁止重入；state 文件同临界区写。
3. 恢复：自动同步默认关，用户显式选方向；epoch 丢弃旧 inFlight；sent 按 `id|remindAt` 保留。
4. round-trip：`item.extra: [key,value,pos][]` + 文件级 unknown blocks + frontmatter 保留；
   条目顺序规范化。
5. 备份：恢复前快照放独立目录、不参与轮转；preview 返回 sha256，restore 校验。
6. 限流：600/min、401 20/min、LRU 1 万键；hops 只影响 req.ip。
7. `.sync-history.json`：内存 ring 50，异步 best-effort，不在写关键路径。
8. 同步中心只读缓存；不要复用 `/api/webdav/status`（`webdav.ts:216` 每次 statRemote 联网）。

## 4. 可测试性

- 验收 #2「带 Authorization 的预检」：浏览器预检不带 Authorization，不可执行。
  改为「无 token OPTIONS → 204 + ACAO/ACAH 正确；GET 无 token → 401」。
- 验收 #3 XFF：假测试。改为 hops=0 时伪造 XFF 不改变 `req.ip`（测试路由回显）；
  hops=1 直暴启动告警；认证始终 401。
- 验收 #4 Electron：手工项不能当门禁，标为非阻塞手工清单，或 Playwright-Electron + xvfb。
- 验收 #8 kill -9：需确定性故障注入钩子。
- 验收 #9 1 分钟：实时等待必 flaky；用 fake timers + 计数 mock，断言单飞。
- 验收 #10/#11：#10 预期本身错（远端会复活恢复时删掉的条目），改为
  「恢复后自动同步暂停 + 显式 pull 预览覆盖数 + 远端独有条目转冲突」；
  #11 逐字节与「不保序」矛盾，改为未知行集合保留 + serialize→parse→serialize 幂等。
