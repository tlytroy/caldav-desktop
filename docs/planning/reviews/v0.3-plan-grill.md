## 1. 为什么 v0.1 不通过

五个硬伤（详细展开见两份附件）：

1. **认证回退逻辑在 Docker / 反代 / Electron 下不成立**。
   `req.ip` 判 loopback 在 Docker bridge、Nginx 反代、`X-Forwarded-For` 伪造、
   Electron `file://`（Origin `null`）面前都不可靠。结论：**fail-closed，始终要求 token**。
2. **锁的范围漏了同步写入**。CalDAV/WebDAV pull、备份恢复都写 `workspace.md`；
   只在 CRUD 加锁等于没锁。结论：**所有写路径统一 `withWorkspaceLock`，网络 IO 在锁外**。
3. **备份恢复会制造状态失配**。恢复旧文件后 etag / reminder sent 全对不上，
   下次同步会把旧数据推回远端。结论：**恢复必须停调度、锁、备份、重置同步缓存、全量重扫**。
4. **迁移框架 YAGNI，且漏掉真正的风险**：解析-序列化往返会丢掉未知字段/注释/顺序。
   结论：**删除迁移框架，改为 round-trip 保留测试 + 只读兼容**。
5. **范围与工期低估**：E1+E2+E3 隐含大量 UI、代理/CORS 测试、Electron 注入、恢复 UI，
   原估 7–11 人日，实际约 15–20 人日。

另外，「本地优先」在前端-only 直连 NAS 的部署形态下是**假的**（本地无数据副本），
计划必须区分「本地模式（Electron / 本机）→ 真本地优先」与「直连模式（浏览器连 NAS）→ 在线模式」。

## 2. 建议的 v0.2 修订（待你确认）

### 2.1 认证（E1 → E1-min）

- **删掉 loopback 回退**。未配置 token 时：只放行 `/health` 与静态资源；
  所有 `/api/*` 返回 401，并给出「如何配置」的提示。
- **token 必有**：
  - Docker：`API_TOKEN` 必须非空，否则启动失败（fail-fast），compose 里显式声明。
  - 桌面：首次启动生成随机 token，Electron 主进程用 `safeStorage` 保存，
    通过 preload 注入 `window.__API_TOKEN__`；浏览器模式才用 localStorage。
- **不设 `/api/auth/*`**：没有额外认证端点，减少爆破面。
- **OPTIONS 豁免 token**（预检不鉴权），但 CORS 白名单严格：
  - 默认同源；`CORS_ORIGINS` 可配；
  - Electron `file://` 走 `Origin: null` 特例（前提是始终要求 token）；
  - dev 模式允许 `http://localhost:5173`；
  - 带 `Vary: Origin`。
- **信任代理**：`TRUST_PROXY_HOPS`（默认 0，不信任 `X-Forwarded-For`）；
  文档给 Nginx / Caddy / Tailscale 示例。
- 限流只做**全局宽松阈值**（如 600 req/min/IP），不设登录接口；token 比较用
  `crypto.timingSafeEqual`。
- 前端 401 统一拦截：弹令牌输入，输入后重试；清除 token 有明确入口。

### 2.2 数据（E2）

- 原子写：**同目录** `workspace.md.tmp` → `fsync` → `rename`；
  失败重试 3 次，仍失败**报错**（不降级直写）；启动/写入前清理陈旧 tmp。
- 锁：单进程 `withWorkspaceLock`，只包「读-改-写」临界区；
  **网络 IO（CalDAV/WebDAV 请求）在锁外**；同步写入、恢复、迁移都走同一把锁；
  多实例写同一文件明确不支持并写进文档。
- 并发不丢更新：锁内重新读文件；对同一 item 的并发字段修改，
  要定义「合并还是报冲突」（建议：workspace CRUD 的 PUT 是字段级 patch，天然保留另一字段）。
- **round-trip 保留**：解析-序列化往返不丢未知字段、未知块、笔记位置；
  加测试（读入带未知字段的文件 → 写出 → 再读，未知内容仍在）。
- 备份恢复：
  - `GET /backups` 列表；`POST /backups/preview` 返回 diff（新增/删除/修改）；
  - `POST /backups/restore`：停调度 → 锁 → 备份当前 → 覆盖 → **重置同步 etag 缓存**
    → 清提醒 sent（或按条目保留）→ 全量冲突重扫；
  - UI 二次确认 + 恢复后 diff 报告。
- **不做迁移框架**；只做版本号检测与显式升级入口（未来需要时）。

### 2.3 同步（E3 → 只读面板优先）

- **E3a 只读同步中心**：聚合现有 CalDAV/WebDAV 状态（不新增调度器），
  显示配置、上次成功/失败、待推送、冲突、最近 20 条历史（只读）。
- **E3b WebDAV 自动同步**（可选，默认关）：
  - 单飞互斥（in-flight）；
  - 遇冲突**暂停并转人工**，绝不自动 force/merge；
  - 间隔变更热更新，不残留旧定时器；
  - 失败指数退避（30s → 60s → …，上限 10min）。
- **不做墓碑删除传播**（v0.3 移出；未来做时键必须是 href，不是 uid）。
- 状态文件规范：`.webdav-state.json` / `.caldav-sync-state.json` / `.reminder-state.json`
  是可重建缓存；`.sync-history.json` 是**日志**（可清空）；备份不是状态，是恢复材料。

### 2.4 部署形态与「本地优先」定义

| 形态 | 数据副本 | 断网/服务器挂 |
| ---- | -------- | ------------- |
| 本地模式（Electron / 本机前后端） | 本地 `workspace.md` | 完整可用（应用内提醒可用） |
| 直连模式（浏览器打开 NAS） | 仅在 NAS | 页面不可用；这不是本地优先，文档要写明 |
| Docker + PWA 安装 | 仅在 NAS | 同上 |

DoD 的「本地优先回归」只针对**本地模式**；直连模式验收改为「服务器不可用时给出明确错误页，
不白屏、不假装保存成功」。

### 2.6 验收（替换原文中不可测项）

1. 不配 token 启动：`/api/workspace/items` → 401；`/health` → 200；loopback 也 401。
2. 带 `Authorization` 的 `OPTIONS` → 204 且 ACAO 正确；无 token GET → 401。
3. `TRUST_PROXY_HOPS=1` 下伪造 `X-Forwarded-For: 127.0.0.1` → 仍 401。
4. Electron `file://` 注入 token 后可读写；无 token 显示令牌输入框。
5. 同一 item 的 `title` 与 `due` 并发修改 → 两字段都保留。
6. 50 请求 + 同时一次 CalDAV pull → 条目数正确、无解析错误。
7. tmp 写完后、rename 前 kill -9 → 重启后旧版本可解析，tmp 被清理。
8. 恢复 3 天前备份 → 覆盖前 diff 预览；恢复后首次同步不全量冲突；旧提醒不重发。
9. 1 分钟自动同步 + 连点手动同步 5 次 → 远端只收到一轮请求。
10. 自动同步遇 412 → 转人工，本地不覆盖，冲突数 1。
11. 未知字段/未知块往返逐字节保留。
12. Docker 构建 + 容器冒烟；`data/workspace.md` 读写正常。
